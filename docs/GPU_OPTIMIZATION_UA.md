# Оптимізація GPU, 14.10.2026

Зібрано Windows x64 Release з Vulkan та окремий CPU EXE. У пакеті є всі ресурси, скомпільовані SPIR-V та запасний CPU-запуск. Vulkan loader встановлюється разом із драйвером відеокарти; DLL із Wine не входять у пакет.

## Що змінено

- Геометрія рельєфу, дерев та декорацій кешується окремо від підрозділів. Незмінні кадри повторно використовують геометрію. Поворот камери й масштаб у межах того самого LOD не перебудовують статичну сцену; зміна фокусу, LOD, ресурсів рельєфу або освітлення інвалідує кеш.
- Вершини й індекси зберігаються у device-local Vulkan буферах. Через staging передаються лише змінені діапазони; після зміни статичної сцени або перевиділення буферів виконується повне завантаження.
- Враховуються розміри staging та GPU allocation у бюджеті геометрії. Додано бар'єри копіювання й окремі семафори завершення для зображень swapchain.
- SPIR-V генерується у каталозі збірки та включається в Windows-пакет. Додано телеметрію пропущених завантажень, резидентної пам'яті й помилок validation.
- Додано перевірки кешу та діапазонів, вимірювач підготовки геометрії і тест справжнього Vulkan малювання з читанням X11-зображення. Linux Vulkan CI запускає synchronization validation.

## Вимірювання

Release, 192 бійці, камера з distance=900, 120 кадрів. Це час CPU-підготовки GPU-геометрії та обсяг планованих передач, а не FPS фізичної відеокарти.

| Показник | До | Після |
| --- | ---: | ---: |
| Підготовка незмінної сцени, p50 | 3,485 мс | 0,0076 мс |
| Підготовка при оновленні симуляції 10 Гц, p50 | 3,487 мс | 0,0077 мс |
| Передача незмінної сцени за 120 кадрів | 363 631 680 байт* | 3 030 264 байт |
| Передача при симуляції 10 Гц за 120 кадрів | 363 631 680 байт* | 3 883 896 байт |

\* Розрахований обсяг повного завантаження тієї самої native-геометрії кожного кадру. Зменшення передач становить 99,17% та 98,93% відповідно. Перша побудова та інвалідація статичного кешу залишаються дорожчими за повторні кадри.

## Перевірки та їх межі

- Linux CPU Release та Debug: 25/25 тестів у кожній конфігурації.
- Linux Vulkan Release: 26/26 тестів із Mesa Lavapipe та Khronos synchronization validation.
- Windows x64 CPU та Vulkan Release: 23/23 тестів у кожній конфігурації під Wine.
- Native Vulkan тест: 13 кадрів, перше завантаження 3 030 264 байт, оновлення підрозділів 44 928 байт, 9 кадрів без передачі mesh, резидентні буфери 6 144 336 байт, 0 validation errors. Перевірено зміну фактичного зображення, поворот/перенесення камери та відновлення після resize.
- Обидва Windows EXE запускаються з готової папки під Wine: завантаження ресурсів, CPU меню/тактичний/стратегічний кадри та завершений бій (VICTORY, tick=517, shots=48). `--smoke-test` примусово використовує CPU і не підтверджує Windows native Vulkan малювання.
- Фізична GPU та Windows 11 недоступні в цьому середовищі. FPS на відеокарті, відповідність Vulkan сцени всім деталям CPU-рендерера та інтерактивний Windows gameplay ще потребують перевірки на цільовому ПК.

## Відтворення

```sh
cmake -S . -B build-linux -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DGZ_ENABLE_VULKAN=OFF
cmake --build build-linux --parallel 2
ctest --test-dir build-linux --output-on-failure
./build-linux/grayzone_gpu_benchmark

# Потрібні Vulkan SDK, glslangValidator, Mesa Vulkan ICD, validation layers та Xvfb.
cmake -S . -B build-vulkan -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DGZ_ENABLE_VULKAN=ON -DGZ_REQUIRE_VULKAN=ON -DGZ_VULKAN_RUNTIME_TESTS=ON
cmake --build build-vulkan --parallel 2
ctest --test-dir build-vulkan --output-on-failure
```

Наступні пріоритети: вимірювання на Windows GPU; кешування території частинами під час переміщення камери; instancing дерев/підрозділів; GPU HUD та матеріали для відповідності CPU-версії. Поточна реалізація використовує один кадр у роботі; багатокадровий конвеєр не впроваджено.
